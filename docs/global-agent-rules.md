# 全局 Agent 协作规范（所有工作区通用）

> 本文件位于 `~/.dsh/AGENTS.md`，由 DSH 内核自动加载到所有会话与工作区。
> 优先级：系统 / 开发者 / 用户直接指令 > 项目级 `AGENTS.md` > 本全局规范。
> 本文件只含「跨项目通用」规则；项目特定规则请写在各项目的 `AGENTS.md`。

## 工作流程铁律（read → plan → patch → verify → review）

1. **五段流程**：任何非只读改动（写 / 删 / 装 / 重启前）必须走
   - **read**：先读相关文件与目录结构，确认改动属于哪一层，先看框架再写代码。
   - **plan**：按下方固定模板输出书面方案，**不执行任何写入**。
   - **门禁**：用户明确批准（"可以 / 执行 / 没问题"）才执行；用户明说"直接做"可跳门禁，但不可跳 plan。
   - **patch**：按已批准方案执行；中途要绕路就停下回到 plan，说明原因重新确认。
   - **verify + review**：给出可核验证据，并回答自检三问——门禁过了吗？验证证据是什么？相似问题扫了吗？
2. **风险收益评估**：每次操作先评估——收益＝解决什么问题；风险＝影响面 / 可逆性 / 是否波及运行中服务；等级＝低 / 中 / 高。高风险另需：先备份 → 预检 → 征得用户确认。
3. **相似问题排查**：每修复一个问题，扫描同类模式（同样的误用 / 缺参 / 越层 / 编码坑），列出疑似清单并询问用户是否一并修复，禁止静默顺手改。
4. **架构层级纪律**：客户端 / 前端不得直接访问数据库、文件系统、操作系统能力，必须走服务层 API；插件经宿主上下文，不直碰内核内部；新功能先问"有没有现成机制"，不重复造轮子。
5. **自迭代**：发现规则碍事或过时，只在 review 阶段提出修订建议，用户批准后修改，不得静默变更。

## 工作区感知

回答涉及工作区具体文件 / 代码 / 配置的问题时，先用搜索 / 读取工具查看相关文件内容，再结合搜索结果回答；不凭记忆或假设回答。

## 安全守则

- 删除 / 清空类命令必须先预检，再列出将被删除的路径与数量；目标必须在工作区内（或用户明确同意）。
- 不自动重启用户的应用 / 服务；改动提交后告知"已就绪，等用户指示"，仅在用户明确要求时重启。
- 高危改动先在临时副本修改并验证，再原子替换正式文件；绝不在运行路径上留下非法中间态。
- `~/.dsh` 下改动先存档再改（可回滚）。

## DSH 开发通用坑位

- 工具可选参数**不能**写 `required:false`（loader 报 "required must be true when present"），省略 required 即可。
- 插件 `inject` 不要写永不解析的服务（如 compaction）；用 `ctx.reflect.get(...)` 惰性解析。
- DSH 文件沙箱为 workspace-write：文件工具只能写当前工作区；写全局 npm / 全局配置用 shell。
- 无控制台环境（桌面壳 / 服务进程）：`spawn` / `execFile` / `execSync` 必须带 `windowsHide:true`，否则闪黑框。
- PowerShell 脚本用纯 ASCII 注释（PS 5.1 会把 UTF-8 无 BOM 中文读成 GBK 导致语法错）；路径参数警惕 `[ ] { } ( ) $ * ?` 元字符与引号配对。
