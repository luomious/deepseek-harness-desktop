## 3.5 隔离装配机制(新增,按用户要求)

> 需求:当变更可能影响系统稳定性时,先在独立隔离空间执行,验证通过再合并回原位置。

**引擎**: `scripts/staged-profile-assemble.ps1`
- **风险判断**: profile 装配类变更(bundles/patch/pnpm)→ 必须隔离;只读预检/备份 → 直接执行;
- **流程**: 隔离(desktop → desktop-staging 快照)→ 执行(应用批次 + pnpm install)→ 验证(`--dump-config` 批次标记全出现)→ 合并(备份 → 三件套原子替换 → 清理 staging → **desktop pnpm install 补依赖**);
- **批次**: batch1 后端 / batch2 模型+MCP(modlens 单包先行)/ batch3 客户端 UI / batch4 收尾;
- **实战验证(该机制抓到 2 个真 Bug)**: ① 合并漏 node_modules → `PackageOverlayNotFoundError`;② 合并漏 mcp-lens tgz → `ENOENT`。均已修复并复验,证明"隔离 → 验证 → 合并"能防住半成品状态;
- **PS 5.1 坑**: .ps1 含中文必须 UTF-8 带 BOM,否则按 GBK 解析报语法错(edit 工具会去 BOM,改后需重加)。

## 3. 防崩溃机制(救生索,已核实)

1. `dsh --profile desktop --patch <文件>` —— CLI 叠加 patch 层,可禁用任意 bundle;
2. 直接编辑 `~/.dsh/profiles/desktop/cordis.patch.yml` 加 `disabled: true`;
3. 备份恢复:`D:\Deepseek-Harness\_backups\20260822-19xxxx\`(desktop + web 六件套);
4. 每插件独立 git commit,可 `git revert`;
5. **modlens 绝不热重载**(adapter 只启动时注册,热重载会卡死服务)。
