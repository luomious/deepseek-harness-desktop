# 火绒信任区配置指引（消除「DSH 自动关闭」的实验）

> 配套报告：[`README.md`](./README.md)（根因与彻底修复）
> 适用：Windows + 火绒安全（本机为 5.x/6.x 系列；两代菜单路径不同，下文都给了）
> 为什么要做这件事：**这不是可选的优化项。** 火绒没有公开 CLI，信任区只能人工添加；而「把 DSH 加白后是否仍自动关闭」是当前**唯一可行**的判别实验 —— 用来确认自动关闭到底是不是火绒引起。

---

## 0. 先明确代价（必读）

| 项 | 说明 |
|---|---|
| 收益 | 判别「自动关闭」的归因；若确为火绒，则同时解决问题 |
| 代价 | 信任区内的对象**不再被查杀、也不再被各项防护检测**（官方原文：「受信任的项目将不会被认为包含风险，也不会被病毒查杀以及病毒防护的各项功能检测」）⇒ 等于在这些路径上**放弃防护** |
| 纪律 | **只加最小集合**（下面 2 类）。**绝不要**加整个盘符（`D:\`）、`Program Files`、`C:\Windows` 等 —— 那会把防护砍掉一大块 |
| 可逆 | 信任区列表可随时逐项「删除」，清除即恢复原状 |

---

## 1. 第一步：先取「实际路径」（不要照抄，构建换版会变）

**已知事实（本报告作者实测）**：DSH 程序目录通过 junction 指向**带构建时间戳**的目录，换版 `promote-build` 后 junction 自动跟随、但时间戳名会变：

| 项 | 值 |
|---|---|
| junction（稳定入口） | `D:\Deepseek-Harness\vendor\deepseek-harness-desktop\dsh-plugin-desktop\dist\win-unpacked` |
| 当前 realpath | `…\dist\win-unpacked-build202608272104\win-unpacked` |
| 可执行文件 | `<realpath>\DSH Desktop.exe`（实测存在） |

⇒ 所以**加白时按下面的 junction 路径加**（或现场取），不要写死带时间戳的那个。

**在 DSH 正在运行时**，用这一行取「此刻真正在跑的那个 exe」路径：

```powershell
Get-Process 'DSH Desktop' | Select-Object -ExpandProperty Path | Sort-Object -Unique
```

> ⚠️ 注意：仓库根目录 `D:\Deepseek-Harness\dist` **并不存在**（别按这个找）。真实位置在 `vendor\…\dsh-plugin-desktop\dist\` 下。

---

## 2. 第二步：只加这两类对象

| # | 对象 | 路径 | 为什么需要 |
|---|---|---|---|
| 1 | **DSH 程序目录** | `D:\Deepseek-Harness\vendor\deepseek-harness-desktop\dsh-plugin-desktop\dist\win-unpacked` | 主进程 / 渲染进程 / `ELECTRON_RUN_AS_NODE` 子进程都从这里启动 |
| 2 | **hy3 网关目录** | `D:\Deepseek-Harness\hy3-gateway\` | 网关 `server.js` 与 `apikey.local.txt` 在此；它是被 detached 拉起、独立存活时间最长的子进程 |

> 3.（可选，范围更大）`D:\Deepseek-Harness\` 整个工作区 —— 因为程序目录本身就在 `vendor\` 下，加工作区**涵盖前两项**，代价是范围最大。只在加白前 2 项后**仍**被拦截时才考虑，且加完观察一轮再决定。

---

## 3. 第三步：添加（两代菜单路径）

### 火绒 6.x

官方 FAQ 的表述是：**「设置 - 信任区」** → 手动添加**文件 / 文件夹 / 程序进程**。

1. 打开火绒安全主界面
2. 右上角 **三横线 / 下箭头** 菜单 → **信任区**
   （或：**设置 → 信任区**）
3. 右下角 **添加文件 / 添加文件夹** → 选中 §2 的对象 → 确定
4. 确认列表中出现该条目

### 火绒 5.x

官方手册：信任区有两个入口 —— **首页下拉菜单**，或**托盘图标右键菜单**；界面内为 **添加文件 / 添加文件夹 / 清除无效项**。

- 若曾经加过白但文件已移动 ⇒ 先点 **清除无效项**，再加新路径。

> ⚠️ 任何**弹窗拦截**出现时，最快路径是点弹窗里的 **「信任此文件、不再拦截」**（官方 FAQ 推荐）——它等价于把该文件加入信任区，且顺手完成取证（弹窗本身就是「谁在拦」的证据）。

---

## 4. 第四步：判定是否生效（关键，别只看「没关」）

加白后**重启 DSH**，然后同时看三个地方：

```powershell
# A) DSH 侧：主进程存活时间（看是否还被短命终止）
Get-Process 'DSH Desktop' | Select-Object StartTime, Id

# B) DSH 侧：网关心跳是否被持续刷新（每 15s 一拍；停了说明主进程又没了）
Get-Item "$env:USERPROFILE\.dsh\hy3-gateway.heartbeat" | Select LastWriteTime

# C) 火绒侧：安全日志 → 主动防御 / 拦截记录（**这才是最直接的证据**）
#    火绒主界面 → 安全日志 → 查看「主动防御」类目
```

判定口径：

| 观察结果 | 结论 |
|---|---|
| A 稳定存活 + C 里**没有** `DSH Desktop.exe` 的拦截记录 | 火绒不是元凶（或已排除）⇒ 需另找原因 |
| A 稳定存活 + C 里**有**（哪怕加白后仍出现） | 火绒在拦、且信任区未覆盖该行为 ⇒ 进 §5 |
| A 仍短命 + C 里**有**拦截记录 | **归因确认 = 火绒** ⇒ 继续 §5 收敛规则 |
| A 仍短命 + C 里**没有**记录 | 不是火绒拦截 ⇒ 回到报告 §4「未验证」项，另设计取手段 |

> 「没被关」不等于「已解决」：必须至少跑完一次 10 分钟以上的完整使用，且 B 的心跳文件持续在动，才算稳定。

---

## 5. 若不生效：把「拦截」变成「可见」（取证手段）

信任区是**排除**；如果拦你的是纯行为规则，它可能仍在动。此时做一件事：**把处理方式从「自动阻止」改成「询问我」**。

- 位置：火绒 **防护中心 → 主动防御**（部分版本为 **安全设置 → 主动防御**，各版本位置略有差异）
- 目的:**弹窗即证据** —— 弹窗会告诉你「哪个程序、触发了哪条规则」
- 拿到这条信息后，有两个收尾方向：
  1. 对该**具体规则**放行（比整目录加白更精准、更安全）；
  2. 若规则不可放行，则对 §2 的两类对象加白。
