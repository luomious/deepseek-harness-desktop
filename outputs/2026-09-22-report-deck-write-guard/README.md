### 行为契约（**不可能弄坏一次本来能跑通的生成**）

| 情况 | 行为 |
|---|---|
| 目标不存在 | 返回 `None`，**什么都不做** |
| 目标已存在 | `shutil.copy2` 复制成 `.bak-<ts>`，打印路径 |
| 备份失败 | **抛异常**（故意 fail-loud）—— 继续写就会毁掉唯一副本 |

**从不拒绝、从不删除、从不修改原文件。** 用 `copy2` 而非 `move`，原文件在新稿写成功前原地不动。

**没有保留策略是故意的**：备份按 `<name>.bak-<ts>` 累积，与本目录既有惯例一致
（如 `README_Nano项目说明.md.bak-20260922-111357`）。清理旧备份是**单独的、需你确认**的操作。
一个短到能审计的守卫，胜过没人看的保留策略。

## §5 ★ 本轮的第 3 次同类自我纠错

校验器把 **`_deck_guard.py:51`** 报成一个"无法解析写入点的生成器" —— 那一行是它**docstring 里的用法示例**。
这已经是**同一类假阳性第 3 次**（前两次：25 行回看窗口误报、把 `os.path.exists()` 输入检查当输出守卫）。

**没有再加一个"按文件名跳过"的补丁**（那只是把问题推迟到下一个写文档的人），
而是用 **`tokenize` 判定"这个匹配是否落在字符串字面量里"**，一次性消灭整类问题：

- docstring 里的示例、**正则里写出来的 `.save(`**、故障注入夹具里的文本，全部自动忽略；
- **取消按文件名跳过**（`SKIP_FILES` 现在为空）—— 不需要维护名字清单；
- `.js` / `.ps1` 没有 tokenizer，按原文匹配，**已在脚本头部明示这条限制**。

顺带把 **`writers` 映射**加进 `--json`（产出路径 → 真实写入脚本），
T5 由此改为**从实时 `writers` 推导**正向对照，**不再依赖可能过期的 `candidates`** ——
测试因此对登记漂移免疫。

## §6 风险 / 收益

**收益**

1. 把"**静默且不可恢复**的覆盖"变成"**有 `.bak-` 可回退**"，**不依赖运行者是否记得**。
2. **不依赖归属判定的结论** —— 5 个脚本里任何一个被误跑，都能救回上一版。
3. 用**本目录既有惯例**实现，不是新造轮子；新生成器只需照 §4 契约加一行。
4. 顺带修掉校验器第 3 次同类假阳性，并新增**登记漂移**可见性（`[W]`）。

**风险**

| 项 | 评估 |
|---|---|
| 是否改变生成**内容** | **否**。只多写一个备份文件，产出字节不变（A/B 断言 A、C、D 已证） |
| 是否可能**阻塞**生成 | **否**。守卫从不拒绝；仅在**备份都写不成**时抛错（此时继续写必然毁掉唯一副本） |
| 解析/路径误判风险 | 备份名 = `<完整路径>.bak-<ts>`，与本目录既有惯例一致 |
| 备份累积 | 每次运行 3 份 × ~1.4 MB；**无保留策略**（故意的，避免擅自删除）。需要清理时是单独操作 |
| 可逆性 | `git checkout -- <4 个脚本>` 即可回退（改动前状态已在提交 `ae3814e`）；新增文件删掉即可 |
| 是否波及运行中服务 | **否**。纯静态文件；与训练任务、Web GUI 无关 |

**等级：中风险（改了 4 个生产脚本）/ 高收益。** 风险由三重验证 + A/B 对照 + git 可回退覆盖。
