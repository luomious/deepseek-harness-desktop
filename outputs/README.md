# outputs/ —— 产出统一归档约定（G2）

> 建立时间：2026-09-10 · 来源：能力审计 **G2「产出统一归档与呈现」**
> 目的：让"生成了什么、在哪、最新是哪份"永远可回答。

## 为什么需要

审计时的现状：`diagrams/` 下 41 个文件，存在大量**同名 + 不同时间戳**的近似副本
（`架构全景-20260907-004009.svg` / `-004556.svg` / `-005035.svg` …、
`v9.2-验收` / `v9.2-复验` / `v9.3` / `v9.4` …），另有一个遗留的 `.tmpdir/*.tmp`。
结果：**没人说得清哪一份是最新的、哪一份被引用过** —— 可追溯性在第一道就断了。

## 约定（新产出一律遵守）

### 1. 目录命名

```
outputs/<YYYY-MM-DD>-<type>-<topic>/
```

- `<type>` 取自**受控词表**（不要自造）：

  | type | 用途 |
  |---|---|
  | `report` | 报告 / 审计 / 结论文档 |
  | `diagram` | 图（架构图、流程图、示意图） |
  | `table` | 数据表 / CSV / 台账 |
  | `slide` | 演示稿 |
  | `doc` | 其他文档（说明、规范、提案） |
  | `data` | 机器可读产物（JSON / 导出） |
  | `export` | 从外部系统导出的东西 |

- `<topic>` 用 kebab-case 英文或简短中文，说明主题，例如
  `outputs/2026-09-10-report-capability-audit/`。

### 2. 目录内必须有入口

每个产出目录里放一个**唯一入口**：网页用 `index.html`，文档用 `README.md` 或
`<topic>.md`，数据用主文件 + `README.md` 说明字段含义。避免"一堆同级文件靠猜"。

### 3. 产出即可查看（硬规则）

产出落盘后**必须做两件事**，缺一不可：

1. 在 [`INDEX.md`](./INDEX.md) 追加一行登记；
2. **立即呈现给用户**（present_files 等），不要只在对话里描述路径。

> 只写进对话 = 等于没产出。用户不该被要求自己去目录里翻。

### 4. 历史只增不改

- 已归档目录**不改名、不删内容**；有新版就新建目录，在 INDEX 里标注 supersede 关系。
- `diagrams/` 标记为 **legacy**：内容保留，但**新产出不再写入**。

## 用什么建目录

```bash
node scripts/new-output.mjs --type report --topic capability-audit
# 先看看会做什么：加 --dry-run
```

脚本会：创建带日期前缀的目录 → 生成占位 `README.md` → 在 `INDEX.md` 追加一行。

## 与既有四件套的关系

本项目的变更记录走四件套（计划文档 + CHANGELOG + memory + 备份），那是**过程记录**；
`outputs/` 是**结果归档**。两者不重叠：过程留痕在 `docs/` 与 `_backups/`，
最终可交付的成品在 `outputs/`。
