# Diagram — 交互式 SVG 图表

## 触发时机

- 用户说「画/生成/帮我搞一张架构图（流程图/时序图/状态图/ER图/部署图/示意图）」
- 用户说「用图形化解释一下 XXX」「图解这个概念」
- 用户说「可视化我的系统/流程/架构」

当用户只是想要一张图时，**主动调用工具 `render_diagram`**，不要只输出 markdown 代码块。
`render_diagram` 会在会话流中渲染交互卡片（用户可复制源码、下载 .svg、缩放、平移），并把 SVG 保存到工作区 `diagrams/` 目录。

## 先想后画（设计思维 · 禁止生搬硬套）

画图前**必须**完成五步思考，禁止拿到主题直接套骨架：

**Step 1 · 内容解构**：这段信息的真实结构是什么？五种基本型：
- **线性流水线**：A→B→C 顺序依赖（如请求处理链）
- **并行泳道**：一个输入分给 N 条并行路径再汇合（如多线程 / 多阶段评审，SLAM 样张即此类）
- **层次包含**：整体-部分、分层架构
- **循环 / 状态**：有回边、状态迁移（如重试、审批流）
- **论证对比**：基线 → 改进 → 终值（如方案对比、消融实验）

**Step 2 · 一句话主旨**：写下「读者看完这张图要带走的一个结论」——图里每个元素都必须服务它，服务不了的就删。

**Step 3 · 布局选型**（结构决定布局，不是反过来）：

| 结构 | 布局 |
|---|---|
| 线性 | TD / LR 单列直排（mermaid 即可） |
| 并行泳道 | 输入 → N 列并行 → 汇合（手绘 SVG 或 mermaid 多 subgraph） |
| 层次 | 嵌套容器由外到内 |
| 循环 / 状态 | 回边 + 状态节点 |
| 论证对比 | 三段式：主线 + 侧卡 + 指标条（**仅此类型用三段式**） |

**Step 4 · 取舍**：节点 >14 个时依次砍——细节降级为副文字 → 降级为图下文字说明 → 删除；**绝不为了全面而塞**。

**Step 5 · 选通道**：结构简单线性 → mermaid（快）；并行泳道 / 复杂构图 → 手绘 SVG（表达力）。mermaid 表达不了的结构别硬套。

## 工具调用契约（两种模式）

**模式 ①（推荐）：Mermaid 自动布局** —— 流程图/架构图/时序图/状态图/类图优先用这个：

```
render_diagram({
  title: '简短标题',
  mermaid: 'flowchart TB\n  A[开始] --> B[处理]\n  B --> C{通过?}\n  C -->|是| D[发布]\n  C -->|否| E[修复]',
  fileName: '可选：文件名词干'
})
```

自动布局引擎（插件内置 vendored Mermaid v11，本地加载、无需联网）把图渲染成**正好适配对话宽度**的大小——字号恒定清晰、无需缩放（WorkBuddy 同款）。节点文字 ≤ 10 字/行；多行代码用真实换行。

### Mermaid 排版规范（WorkBuddy 级观感）

1. **按类别上色**：2–4 个 `classDef`，色板用下方「WorkBuddy 视觉规范」三族色（中性纸色=输入输出 / 靛蓝主色=核心流程 / 终值绿=最终成果），`class` 挂到节点——同色只表同类。
2. **双行标签**：主标题 + `<br/><small>小字说明</small>`，每行 ≤ 12 字。
3. **分组**：同阶段节点用 `subgraph` 归组（可配 `direction LR/TB`），容器自动留白。
4. **方向**：流程链 → `TD`；并行多列/流水线 → `LR`。
5. **间距交给引擎**：渲染器统一控制疏密（不挤不散），**禁止**用空节点或空行撑距离。
6. 节点总数建议 ≤ 14，超出拆两张图。

示例骨架（仅 P5 论证对比类适用，勿生搬硬套）：

```
flowchart TD
    U(["输入"]) --> T
    subgraph T["阶段名"]
        B["主标题<br/><small>小字说明</small>"] --> C{"判断?"}
    end
    C -->|是| D["结果<br/><small>说明</small>"]
    C -->|否| E["回退<br/><small>说明</small>"]
    classDef io fill:#F1EFE8,stroke:#888780,color:#2C2C2A
    classDef proc fill:#EEEDFE,stroke:#534AB7,color:#26215C
    classDef ok fill:#E1F5EE,stroke:#0F6E56,color:#04342C
    class U io
    class B proc
    class D ok
```

**模式 ②：手绘 SVG** —— 需要像素级精确布局（分层架构、自定义视觉）时用：

### WorkBuddy 视觉规范（样张提炼 · 手绘 SVG 与 classDef 通用）

参考样张：`plugins/dsh-diagram-renderer/skill/exemplar-workbuddy.svg`（出图前对照）。

**三族色板（每族 fill / 描边 / 标题字 / 副文字 四件套，色彩即语义）：**

| 族 | 语义 | fill | 描边 | 标题字 | 副文字 |
|---|---|---|---|---|---|
| 中性纸色 | 输入 / 输出 / 基线 | #F1EFE8 | #888780 | #2C2C2A | #5F5E5A |
| 靛蓝主色 | 核心流程 / 改进对象 | #EEEDFE | #534AB7 | #26215C | #534AB7 |
| 强调淡靛 | 重点小件 / 徽章 | #CECBF6 | #534AB7 | #26215C | #3C3489 |
| 终值绿 | 最终成果（全文唯一） | #E1F5EE | #0F6E56 | #04342C | #0F6E56 |

**线条与形状：**
- 描边一律 **0.5px 发丝线**（精致感的关键，禁用粗框）
- 圆角：主节点 rx=8，小件/徽章 rx=5
- 箭头：1.5px `#888780` 灰线 + **开口 chevron 箭头**（非实心三角）：
  `<marker id="aw" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="6" orient="auto-start-reverse"><path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/></marker>`

**字级：** 主标题 14px/weight 500；副文字 12px；小件 11px；一律 `dominant-baseline="central"` 垂直居中 + `text-anchor="middle"` 水平居中。

**构图三段式（仅 P5 论证对比类使用，其他结构按「先想后画」选型表走）：**
1. **主流程列**（左，垂直流，等宽节点对齐）；
2. **右侧注释卡**（改进①②③…，与对应节点水平对位，短横线箭头连接）；
3. **底部指标条**（小标题 + 4 张并排数据卡：基线=中性、过程=主色、终值=绿）。
4. 节点内可嵌并列小 chips（约 70×22 rx=5）表达并列子项。

**克制原则：** 无渐变 / 无阴影 / 无动效 / 无图标；同族只表同类，全文只允许一处终值绿。

```
render_diagram({ title: '标题', svg: '<svg ...>...</svg>', fileName: '可选' })
```

选择原则：**先按「先想后画」的布局选型定结构**，再选通道——结构简单线性 → mermaid（快）；并行泳道 / 层次 / 复杂构图 → 手绘 SVG（表达力强）。mermaid 画不出的结构不要硬套。

### 自适应出图原则（v5 · 免缩放适配卡片展示）

卡片按「fit-width + 高度随图」自适应渲染（卡片即相框，用户零缩放），出图时遵守以下约束保证 fit 后直接可读：

1. **按显示尺寸作画（核心）**：画布宽 = 最终显示宽（960–1050px，fit 系数 ≥0.8），字号直接按可读标准写——节点主字 ≥17px、副字 ≥13px、层标题 ≥19px、主标题 ≥28px（fit 后等效约 14/11/16/24px）。**禁止**画 1300px+ 大画布再靠 fit 缩小——那会把 15px 字缩到 10px 以下（2026-09-05 用户实测反馈「字体小」的根因）。
2. **宽高比**：画布高 ≤ 宽 × 0.85——fit 后高度落在 720px 上限内，整图免滚动完整可见；超高内容拆成多张或改横排。
3. **信息密度**：一行 ≤3 节点、一屏 ≤3 层；字号变大后单行容量变小，塞不下就砍副文字/拆图，不靠缩放救。

## 展示策略：自适应交互卡为主，图片行兜底（2026-09-05 v5 定稿）

交互卡（**自适应免缩放** / 下载 / PNG / 全屏）会在回复下方**自动出现**——默认**不要**把 markdown 图片行粘贴进回复，否则同一张图会出现两遍（静态图 + 交互卡）。卡片即相框：宽度铺满对话列、高度随图宽高比走（上限 78vh/720px），整图直接可见免缩放；超高图才在卡内垂直滚动。

**仅在以下情况粘贴图片行**（从工具返回取 `![标题](http://127.0.0.1:<端口>/diagram-files/<文件名>)`，端口通常 43120，文件名取返回里 `path` 的文件部分）：

1. 用户明确要求把图嵌在文字中间（图文混排）；
2. 本会话此前交互卡渲染异常、或用户尚未刷新过页面（兜底可见性）；
3. 用户要把图拿去别处分享，需要直链。

- 卡片未出现时，先请用户刷新页面（client bundle no-cache，刷新即加载最新），再考虑兜底。
- mermaid 模式没有图片行（存的是 .mmd 源码），展示只走交互卡。

## SVG 编写规范

1. **必须有 `<svg ...>...</svg>` 根元素**；建议带 `viewBox="0 0 W H"`（支持缩放），并给 `width/height`（默认渲染尺寸）。
2. **尺寸**：画布宽 960–1050 px（**按显示尺寸作画**，fit 系数 ≥0.8，详见「自适应出图原则」）；整体控制在 80 KB 内（上限 512 KB）。
3. **字号（重要——对话里图会被等比缩放到列宽，字号小了根本看不清）**：
   - 主标题：**≥ 26px**
   - 容器/层标题：**≥ 19px**
   - 节点主文字：**≥ 17px**（粗体）
   - 节点副文字/注释：**≥ 13px**
   - 宁可少放文字也要保证大字号；一屏 960×760 最多约 3 层 × 3 节点，超出就拆图。
4. **排版呼吸感（强制——拥挤 = 废图）**：
   - 节点之间水平间距 **≥ 40px**，层容器内边距 **≥ 40px**，层与层之间留 **≥ 40px** 放箭头；
   - 每行最多 **3 个节点**（1000px 宽画布）；要放 4 个就加宽画布到 1300px 或拆行/拆图；
   - 节点内最多 **1 行主文字 + 1 行副文字**，主文字 ≤ 10 个汉字；更多内容放图下方文字说明里；
   - 节点统一等宽、列对齐（同一列 x 相同），箭头短而直，不交叉；
   - **留白即设计**：宁可画布大、留白多，不可挤满；底部说明条与主图留 ≥ 40px。
5. **禁止**：`<script>`、`on*` 事件属性、非 `#` 开头的 `href/src`（会被清洗，加了也没用）。
6. **白色画布（必须）**：根元素内第一个子元素放全幅背景 rect——`<rect x="0" y="0" width="100%" height="100%" fill="#ffffff"/>`（深色主题下无背景 = 黑底不可读；渲染器会自动补，但作者端写上最稳）。
7. **样式**：用 `fill`/`stroke`/`font-family` 等内联属性；避免依赖外部 CSS/字体（下载后单文件也能看）。
8. **结构化（可选但推荐）**：给每个节点 `<g id="node-xxx" data-name="节点名">…</g>`，便于后续交互增强。
9. **可读性**：节点加 `rx` 圆角、文本 `text-anchor="middle"` 居中、连接线用 `marker-end` 箭头。

## 动效（可选 · 让图"动起来"）

在 SVG 根内嵌 `<style>` 即可加**纯 CSS 动效**（无 JS；`<script>` 会被清洗，`<style>` 保留，两个通道都生效）：

- **箭头流动**：连线加 `class="flow"`，CSS：`.flow{stroke-dasharray:10 8;animation:dshflow 1.1s linear infinite}@keyframes dshflow{to{stroke-dashoffset:-18}}`
- **节点/层渐入**：容器加 `class="pop d1"`（d1/d2/d3 递进延迟 .15s），CSS：`.pop{opacity:0;animation:dshpop .5s ease forwards}@keyframes dshpop{from{opacity:0;transform:translateY(6px)}to{opacity:1;transform:none}}`
- **克制原则**：只给关键路径或 1–2 处强调加动效；并加 `@media (prefers-reduced-motion:reduce){*{animation:none !important}}` 尊重无障碍。

## 常见图类型要点

| 类型 | 结构建议 |
|---|---|
| 架构图 | 分层容器（<g> 背景块）+ 服务节点 + 连线 |
| 流程图 | 圆角矩形（开始/结束）、矩形（处理）、菱形（判断）、箭头 |
| 时序图 | 参与者头部 + 纵向虚线生命线 + 横向箭头消息 |
| 状态图 | 圆角状态节点 + 迁移箭头 + 起止圆点 |
| ER 图 | 实体矩形 + 属性圆 + 关系菱形（或简化：实体+连线+标注） |
| 部署图 | 节点机柜/容器块 + 内部组件 + 网络连线 |

## 流程

1. 理解需求 → 选择图类型；
2. 用 SVG 组织好布局（先算好坐标网格，如每格 40px）；
3. 调用 `render_diagram` 传入 title + svg；
4. 卡片出现后，如需修改，重新调用并说明改动点。

## 注意

- 图要**一次画好**：SVG 是结构化代码，别边画边试；先规划坐标再写。
- 复杂系统可拆成多张图（每张聚焦一个层次），不要塞一张图。
- 用户对图提出修改意见时，基于原 SVG 增量改，重调 `render_diagram`。
